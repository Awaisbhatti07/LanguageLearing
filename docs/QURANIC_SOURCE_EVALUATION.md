The [CC BY 3.0 deed](https://creativecommons.org/licenses/by/3.0/) allows adaptation, whereas Tanzil's own text page requires preservation. Our proposed path follows verbatim preservation without attempting to resolve broader legal interpretation. Corpus GPL compatibility and the effect of its extra wording remain unresolved; this document does not determine that the entire application must adopt a particular license.

## Proposed acquisition and integrity contract

This is an implementation proposal, not an executed importer or approval manifest:

1. Acquire from the official site after the milestone sequencing decision. Record the selected options, requested/final HTTPS URL, source release, acquisition time, exact bytes, SHA-256, size and full supplied notices. A locally computed hash fingerprints that download; it does not independently prove authenticity. No artifact/hash has been pinned in this checkpoint.
2. Retain the raw file unchanged. Parse strictly as bounded UTF-8 XML without DTDs/external entities. Keep original decoded ayah text separately from metadata, annotations and learner records. Do not trim, NFC-normalize, strip harakat/tatweel, replace letters or append chapter-opening text to the original. Search keys and display spans are separate derived fields.
3. Verify unique references, source order/completeness, chapter-opening handling and an independently checked per-chapter reference inventory. Preserve every text field through parse/store/export. Fail on malformed, missing, duplicate or mismatched records; never repair religious data automatically.
4. Require exact-source offsets and alignment evidence for every displayed word/segment. Handle source-version boundary changes and multi-segment/multiple-stem cases explicitly. Keep morphology IDs and source versions separate from immutable original text; unmatched annotations cannot enter lessons.
5. Produce distinct, versioned frequency methods: exact surface-token occurrences, annotated lemma occurrences, annotated root occurrences and segment occurrences. State segmentation, scope, chapter-opening/sign treatment, missing annotations and tie rules. Publish counts only with occurrence references and reproducible reconciliation tests. No counts or rankings are supplied here.
6. Validate the complete candidate before any transaction; preserve old learner records and immutable content snapshots. Export schemas and test explicit migrations if storage changes. Reject unapproved data, stale hashes, altered notices, inconsistent references, bad alignment and cross-source-version matches.

## Next concrete scope

Recommended next implementation, **after an explicit sequencing exception or M5 acceptance**, is a Tanzil-only acquisition/integrity tool with synthetic nonreligious fixtures, separate raw storage and notice verification. Keep it outside the application's bundled content until source verification and required review pass. Defer morphology-derived ranks, meanings and Quranic learning screens until their independent rights/alignment/review gates are satisfied. No source email or permission request is sent on the user's behalf.
