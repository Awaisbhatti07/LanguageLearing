# Content and practice format

Content packs are UTF-8 JSON in `app/src/main/assets/content/`. Schema v1 has a stable pack ID, monotonically increasing version, one track/level, source/review provenance, ordered units and complete lesson records. The engine rejects unsupported schema/types, invalid/duplicate IDs, missing teaching fields, oversized/deep JSON, malformed Unicode and unsourced Quranic packs. Original Arabic display text and harakat are preserved.

Each lesson includes objectives, Roman Urdu explanations/rules, examples, vocabulary meanings/word classes/pronunciation guidance, speaking prompts, review tags and at least two real exercises; starter lessons also include reading. Device-TTS references must exactly match the displayed example and track language. Pending language review is distinct from structural validation.

Activity kinds: `single_choice`, `multi_choice`, `fill_blank`, `sentence_order`, `match_pairs`. Grading awards one point for a wholly correct activity; no partial scores are implied. Fill blanks normalize NFC/whitespace and optionally case, preserving Arabic diacritics and punctuation. Choice IDs must exist; ordering/matching must use each item exactly once. Identical repeated words are interchangeable in ordering.

A2 adds the seventh kind, `paragraph_writing` (model/validation/persistence/Compose checks passed). Alongside common ID/prompt/Roman Urdu feedback, it contains a 2–8 item `checklist` of stable IDs/text, `modelParagraph` and `modelMeaningRomanUrdu`. Its distinct `paragraph_text` answer stores original `text` (nonblank, at most 2,000 UTF-16 characters, well-formed Unicode, no prohibited controls) and unique known `checkedCriterionIds`. Unchecked items are allowed. Model/checklist fields are required and bounded. This is saved self-practice: arbitrary valid writing receives no automatic grammar or quality score. A lesson must include at least one scored activity, and all activities must be submitted to finish the run. Quiz points and denominator include only the six scored activity kinds; the seven-activity A2 writing lessons have six scored questions.

Paragraphs save only on explicit Save paragraph, using existing immutable session/answer records; repeated submission cannot overwrite the original writing. Unsaved drafts are not promised to survive leaving the activity. Feedback/results show the original prompt, learner text/checks and a clearly labelled possible example. Study on another run displays the most recent saved paragraph, resolved from its original session snapshot so content updates cannot reinterpret it under a new prompt. The DAO uses immutable attempt insert order (SQLite rowid) rather than adjustable wall-clock ordering. Room remains v3; no table/entity/schema change is needed. Older app binaries do not understand this new discriminator. Validation, immutable retries, scoring, reopening/version changes/equal or backwards clocks and saved original prompts passed focused regressions; Compose save/self-review/resume and all historical migration/lesson tests passed in the approved 53-core/51-app run. Device appearance remains unverified.

Listening implementation (model/grading/persistence/JVM UI checks passed): pack v3 additionally uses `listening_choice` with `speech` (`text`, supported `languageTag` matching the track), `options` and `correctOptionId`. Its distinct `listening_selection` answer carries `optionId` and `mode` (`AUDIO` or `READING_ALTERNATIVE`); plain choice answers are invalid. The transcript is not displayed until a durable reading selection or saved feedback. A current playback request must finish before audio mode is stored. Missing/error/interrupted playback cannot satisfy that gate. Reading alternatives are always available and never become audio credit during that session, including after navigation/recreation/replay. Results identify both modes; all points remain general practice rather than listening/CEFR mastery. Older content/answer payloads remain supported; old app versions cannot consume the new activity discriminator. Physical-device audio quality remains unverified.

Imports validate all bundled packs before an atomic write. Same/older pack versions do not downgrade stored content. Updates preserve existing learner records, cannot remove old lesson IDs, cannot steal another pack's lesson IDs and cannot move an old ID to a different track/level. Content replacement uses Room upsert; no destructive database reset is permitted.

The A1 implementation uses a separate `english-a1-beginner` v1 pack rather than changing A0 IDs or level metadata. Positions restart inside each pack; the catalog query orders explicit CEFR level first, then pack and position, so A0 remains before A1. This needs no database migration. Content/key/order/preservation/navigation checks passed in the approved 43-core/44-app run; both packs and the ordering query are present in the built APK. Qualified language/device-audio review remains pending.

A2 uses a separate `english-a2-elementary` v1 file with its own `en-a2-` identifiers. Existing asset discovery imports it without changing A0/A1 source content. The existing level-ordering query places A2 after A1; reversed-import and A0/A1 data-preservation tests passed. The current APK includes all three source-identical packs (50 lessons/302 activities).

B1 source adds a separate `english-b1-intermediate` v1 pack with `en-b1-` identifiers, 24 lessons/148 activities. It reuses the same six scored kinds and four `paragraph_writing` activities, with no model/validator/grader/UI/repository/DAO/schema/dependency changes. The existing asset loader discovers all JSON files, and the existing catalog query already orders B1 after A2. Four new writing tasks save original text/checks/model feedback through the A2 implementation; the standalone practical-message lesson starts with writing, and the three other writing tasks follow their six quizzes. New B1 content/key and four-level preservation/navigation regressions are authored but unexecuted. The current APK does not contain B1. Device voice references remain plain English text; connected-speech teaching does not promise a TTS voice demonstrates weak forms or that a comprehension answer assesses pronunciation.

Opening a lesson creates or resumes a unique active practice session with an immutable copy of that lesson. Answers save by session/exercise/position. Each successful submission persists exactly once; retries return the original result. On the final answer a single transaction finishes the session, stores completion and updates the best ratio and run count. A completed lesson means an assessment was finished; it does not imply mastery or CEFR proficiency. Repeated runs are separate assessments; the daily goal counts distinct completed lessons for the local device day.

Sessions allow resumption after navigation/process recreation and remain tied to the original snapshot through a content update. The Review tab currently lists completed lessons for voluntary repeat practice; scheduled SRS remains M7. Speaking prompts are self-practice; no automatic pronunciation score or AI teacher is claimed.

Database v3 adds `listening_presentations` keyed by session/exercise, separate from immutable answers. Migration 2→3 only creates that table; the 1→2 migration and historical schemas are retained. The generated v3 schema was inspected, and migration tests from historical schemas plus exact pack v1/v2 upgrade fixtures passed. Existing sessions keep their original question count when pack v3 appends listening questions; only newly started sessions receive them.

Religious content is intentionally rejected by this general starter-pack pipeline until M6 adds licensed original text, separate morphology/annotations, reference/word alignment, reproducible frequency methods and release-critical integrity checks.
